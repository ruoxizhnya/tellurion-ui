# 0001 · openapi 单一真相且不直连 DB

- **状态**：已裁决（来源：docs/openapi.yaml（core，`//go:embed`）/ ui README「跨仓契约」/ ADR-D7）
- **场景**：前端需要的数据形状只有后端知道。历史上出现过两种省事做法：复制一份 openapi 到前端、或直接连库查个"临时报表"。前者必然漂移（两边各自维护），后者让鉴权与字段语义全部失控，还制造出第二个写者。
- **决策**：① 契约唯一真相是 core 的 `openapi.yaml`（嵌入二进制，`GET /api/openapi.yaml` 直出），本仓**不复制**；② 所有数据经 `/api`，禁止任何形式的直连数据库；③ 契约变更由 core 先改，前端跟随，e2e 兜底。
- **理由**：契约的价值在于"只有一份"。复制一份的收益是省一次请求，代价是两份真相永远对不齐 —— 而且出错时没人知道哪份是对的。
- **代价 / 后果**：① 前端要看契约必须去 core 仓或调 `/api/openapi.yaml`（多一步）；② 契约变更需要两个仓联动，节奏受 core 约束；③ 没有自动生成的类型时，字段改名只能靠 e2e 与 review 发现。
- **替代关系**：无（本仓首条）
